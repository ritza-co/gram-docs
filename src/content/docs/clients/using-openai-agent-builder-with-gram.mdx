OpenAI's **Agent Builder** is a visual drag-and-drop canvas for creating multi-agent workflows. Part of OpenAI's AgentKit suite [launched in October 2025](https://openai.com/index/introducing-agentkit/), Agent Builder lets you design workflows visually, connect to external tools via MCP servers, and deploy them without writing code.

![Screenshot of multi-agent workflow with If/else routing](/img/guides/agent-builder/multi-agent-handoff.png)

When combined with [Gram-hosted MCP servers](/gram-quickstart), Agent Builder gives your agents safe, authenticated access to your APIs and tools through visual workflows.

This guide shows you how to build a visual workflow in Agent Builder using a [Gram-hosted MCP server](/blog/the-easiest-way-to-host-mcp-servers) for Taskmaster, a full-stack CRUD application for task and project management. Taskmaster includes a web UI for managing projects and tasks, a built-in HTTP API, OAuth 2.0 authentication, and a Neon PostgreSQL database for storing data. Try the [demo app](https://taskmaster-speakeasyapi.vercel.app/) to see it in action.

You'll learn how to build a visual workflow, connect it to your Gram MCP server, and deploy it using ChatKit or the Agents SDK.

Find the full code and OpenAPI document in the [Taskmaster repository](https://github.com/speakeasy-api/taskmaster).


## Understanding OpenAI's AgentKit ecosystem

OpenAI introduced **AgentKit** as a complete toolkit for building, deploying, and optimizing AI agents. Understanding the different components helps clarify the sometimes confusing terminology:

### AgentKit components

**AgentKit** is the umbrella term for OpenAI's complete agent development platform, which includes:

1. **Agent Builder** (this guide): A visual canvas for creating and versioning multi-agent workflows with drag-and-drop nodes, MCP connections, and custom guardrails. Currently in beta.

2. **ChatKit**: A toolkit for embedding customizable chat-based agent experiences in your product. Generally available to all developers.

3. **Connector Registry**: Consolidates data sources into a single admin panel across ChatGPT and the API, including pre-built connectors like Dropbox, Google Drive, SharePoint, and Microsoft Teams, as well as third-party MCP servers. Beginning beta rollout to Enterprise customers.

4. **Enhanced Evaluations**: Tools for trace grading, dataset testing, and automated prompt optimization. Generally available to all developers.

### How it differs from other OpenAI tools

- **[OpenAI Agents SDK](/api-clients/using-openai-agents-sdk-with-gram-mcp-servers):** A Python framework for building agents programmatically with code. Use this when you need full programmatic control, complex logic, or want to embed agents in existing applications.

- **[ChatGPT Developer Mode](/clients/using-chatgpt-developer-mode-with-gram):** Adds custom MCP connectors directly to ChatGPT's web interface for end-user interactions. Use this when you want to give ChatGPT access to your tools without building custom workflows.

- **Agent Builder (this guide):** A visual workflow canvas for building multi-step agent workflows without code. Use this when you want to create complex workflows visually, chain multiple agents together, or quickly prototype agent behaviors. You then deploy the workflow via ChatKit or download the SDK code.

## Understanding the Agent Builder workflow

Agent Builder follows a three-step process for creating and deploying agent workflows:

1. **Design your workflow:** Use the visual canvas to compose agents, add MCP nodes for external tools, configure guardrails, and define control flow logic
2. **Publish your workflow:** Create a versioned snapshot with a workflow ID
3. **Deploy your workflow:** Either embed it in your app using ChatKit (recommended) or download the Agents SDK code to run it yourself

Let's walk through each step.

## Building your workflow in Agent Builder

### Accessing Agent Builder

Log in to the [OpenAI Platform](https://platform.openai.com/) and navigate to [Agent Builder](https://platform.openai.com/agent-builder).

### Creating a new workflow

Click **+ Create** or **Open Agent Builder** to start a new workflow. You can start from a template or from a blank canvas.

Agent Builder provides templates for common workflow patterns like customer service automation, homework helpers, and Q&A agents. For this tutorial, we'll start from a blank canvas.

Every workflow starts with a **Start** node. The Start node defines inputs to your workflow—for chat workflows, it appends user input to conversation history and exposes it as `input_as_text`.

![Screenshot of Agent Builder interface showing node palette and canvas](/img/guides/agent-builder/agent-add-tools.png)

### Understanding nodes

In Agent Builder, you compose workflows by inserting and connecting nodes. Each connection between nodes becomes a typed edge. Agent Builder provides several node types:

**Core nodes:**
- **Start**: Define workflow inputs
- **Agent**: Configure agent instructions, tools, and model settings
- **Note**: Add comments and explanations (doesn't affect execution)

**Tool nodes:**
- **File search**: Retrieve data from OpenAI vector stores
- **Guardrails**: Add safety checks for PII, jailbreaks, hallucinations, and content moderation
- **MCP**: Call third-party tools and services via MCP servers

**Logic nodes:**
- **If/else**: Add conditional branching using Common Expression Language (CEL)
- **While**: Loop on custom conditions
- **Human approval**: Defer to end-users for approval before continuing

**Data nodes:**
- **Transform**: Reshape outputs (for example, object → array)
- **Set state**: Define global variables for use across the workflow

See the [Node reference documentation](https://platform.openai.com/docs/guides/node-reference) for complete details on all available nodes.

### Adding an Agent node

1. From the node palette on the left, drag an **Agent** node onto the canvas
2. Connect the **Start** node to the **Agent** node by dragging from the Start node's output
3. Click on the **Agent** node to configure it:

   - **Name:** `Task Manager`
   - **Instructions:** `You help users manage their tasks and projects using Taskmaster. Be helpful and conversational. When creating tasks, always confirm the details with the user.`
   - **Model:** Select `gpt-5` or your preferred model

Keep each agent well-defined in scope. You can have multiple agent nodes in a workflow, each specialized for different tasks.

### Adding MCP tools to your Agent

Instead of adding a separate MCP node, you'll add MCP tools directly to your Agent node. This is how Agent Builder connects to external MCP servers:

1. Click on your **Agent** node to open its configuration panel
2. Scroll down to the **Tools** section
3. Click the **+** button to add a tool
4. Select **MCP server** from the dropdown menu (under "Hosted")

![Screenshot showing tool options in Agent node](/img/guides/agent-builder/agent-add-tools.png)

This will open the "Connect to MCP Server" dialog where you'll configure your Gram MCP server connection.

#### Configure the MCP server connection

In the "Connect to MCP Server" dialog, fill in your Taskmaster MCP server details:

- **URL:** Your Gram Hosted URL (for example, `https://app.getgram.ai/mcp/your-taskmaster-slug`)
- **Label:** A unique identifier for this MCP connection (for example, `taskmaster_mcp`)
- **Description:** Brief description of what the MCP server does (for example, `A Todo app`)
- **Authentication:** Select **Custom headers** from the dropdown
  - For **Pass-through Authentication:** Add header `TASKMASTER_API_KEY` with your Taskmaster API key
  - For **Managed Authentication:** Add header `Authorization` with value `Bearer YOUR_GRAM_API_KEY`
  - Click **+ Header** if you need to add additional headers

![Screenshot showing the Connect to MCP Server dialog](/img/guides/agent-builder/fill-mcp-server-details.png)

:::note[Authentication Headers]
The exact authentication header depends on your Taskmaster MCP server configuration. Refer to your [Taskmaster MCP server setup](/examples/creating-taskmaster-mcp-server) for the correct header name and format.
:::

Click **Connect** to establish the connection.

#### Wait for connection

Agent Builder will connect to your Gram server and fetch the available tools. This may take a few seconds:

![Screenshot showing connection in progress](/img/guides/agent-builder/taskmaster-mcp-details-loading.png)

#### Select tools and configure approval

Once connected, you'll see a list of available tools from your Taskmaster MCP server:

![Screenshot showing available Taskmaster tools](/img/guides/agent-builder/taskmaster-mcp-select-tools.png)

Configure the following settings:

- **Custom headers:** Review and confirm your authentication headers are correct
- **Approval:** Choose whether tool calls need explicit approval:
  - `Always require approval for all tool calls`: Require approval for every tool call (safest for testing)
  - `Never require approval`: Skip approvals for all tools (recommended for trusted servers in production)
  - Custom configuration: Approve specific tools automatically while requiring approval for others
- **Tools:** Select which tools to enable. By default, all tools are selected. You can:
  - Uncheck tools you don't want to use
  - Click **+ Widget** next to each tool to configure custom UI widgets (optional)

The available Taskmaster tools include:
- `taskmaster_create_task`: Create a new task
- `taskmaster_create_project`: Create a new project
- `taskmaster_update_task`: Update an existing task
- `taskmaster_get_tasks`: List all tasks
- `taskmaster_get_admin_projects`: Get projects
- And more...

Click **Done** or close the dialog to save your MCP server configuration.

#### Verify the MCP tool is added

Back in the Agent node configuration, you should now see the MCP server listed under **Tools**:

![Screenshot showing MCP tool enabled in Agent](/img/guides/agent-builder/tool-enabled-preview-button.png)

The Agent can now use all the tools from your Taskmaster MCP server when responding to user requests.

:::tip[How MCP Tools Work in Agent Builder]
When you add an MCP server to an Agent node:
- Agent Builder fetches tool definitions from your Gram server once at connection time
- The agent can then call these tools as needed during workflow execution
- All tool calls and responses are visible in the Preview and trace view for debugging
- This uses the same underlying technology as the [Responses API MCP tool](https://platform.openai.com/docs/guides/tools-connectors-mcp)
:::

### Adding Guardrails (Optional)

For production agents, it's recommended to add guardrails to protect against unwanted behavior:

1. From the node palette, drag a **Guardrails** node onto the canvas
2. Connect it in your workflow (typically after the Agent node)
3. Click on the Guardrails node to configure safety checks:
   - **Personally identifiable information:** Toggle on to prevent exposure of PII
   - **Moderation:** Toggle on to filter inappropriate content
   - **Jailbreak:** Toggle on to block attempts to override agent instructions
   - **Hallucination:** Toggle on to validate agent responses against tool outputs
   - **Continue on error:** Choose whether to continue the workflow if a guardrail fails

![Screenshot of Guardrails node configuration](/img/guides/agent-builder/optional-guardrails.png)

Guardrails are pass/fail by default. When a guardrail fails, you can either:
- End the workflow (safest option)
- Return to the previous step with a warning
- Continue with modified output (if "Continue on error" is enabled)

For the Taskmaster workflow, guardrails are optional but recommended for production use.

### Preview and test the workflow

Agent Builder provides a **Preview** feature for interactive testing:

1. Click **Preview** in the top navigation
2. In the preview panel, enter a prompt:
   ```
   Create a new task: Review OpenAI Agent Builder documentation
   ```

3. Watch the workflow execute:
   - The Start node captures your input
   - The Agent interprets your request
   - The Agent has access to all Taskmaster tools from your MCP server
   - The Agent calls the appropriate tool (for example, `taskmaster_create_task`)
   - The workflow returns a confirmation message

You can observe the execution in real-time, including which tools are called and what data is passed.

4. Try additional prompts to test different tools:
   ```
   What tasks do I have?
   ```
   ```
   Update my documentation task to mark it as in progress
   ```

Here's what the Preview interaction looks like when updating a task:

![Screenshot showing task update in Preview mode](/img/guides/agent-builder/update-task.png)

You can observe the execution of each node, inspect data flowing between them, and review trace details for debugging.

## Publishing your workflow

Once you're satisfied with your workflow's behavior:

1. Agent Builder autosaves your work as you go
2. Click **Publish** in the top navigation (next to the Preview button)
3. Publishing creates a **versioned snapshot** of your workflow and generates a **workflow ID**
4. You can create multiple versions and specify which version to use in deployments

The workflow ID looks like: `wf_68df4b13b3588190a09d19288d4610ec0df388c3983f58d1`

You'll use this ID to deploy your workflow in the next step.

## Deploying your workflow

After publishing, you have two deployment options available through the **Code** button in Agent Builder's top navigation.

### Option 1: ChatKit (Recommended)

**ChatKit** is the easiest way to deploy your Agent Builder workflow. It provides an embeddable chat UI that connects to your workflow as the backend, handling streaming responses, conversation threads, model thinking visualization, and custom widgets for displaying data and interactive elements.

#### Design your UI with ChatKit Studio

Before implementing ChatKit in code, you can design and customize your chat interface visually using **[ChatKit Studio](https://chatkit.studio/)**. The **[ChatKit Playground](https://chatkit.studio/playground)** lets you choose light or dark modes, customize colors and typography, adjust message bubble styles, and set up starter prompts—all with a real-time preview.

You can also create custom widgets without code using the **[Widget Builder](https://widgets.chatkit.studio/)**. Browse prebuilt templates for cards, lists, and forms, customize them to match your design, and copy the generated JSON to use in your integration. #### Implementation example

In Agent Builder, click **Code** → **ChatKit** and copy your workflow ID. Optionally design your UI in ChatKit Studio first, then follow the [ChatKit quickstart](https://platform.openai.com/docs/guides/chatkit) to create a server endpoint, install the ChatKit React bindings (`npm install @openai/chatkit-react`), and embed the chat widget in your application.

Here's a simplified example:

```typescript
// Server-side: Create ChatKit session with your workflow ID
import { OpenAI } from "openai";

const openai = new OpenAI();

export async function createChatKitSession() {
  const session = await openai.chatkit.sessions.create({
    workflow: { id: "wf_YOUR_WORKFLOW_ID_HERE" },
    user: "user_device_id",
  });

  return { client_secret: session.client_secret };
}

// Client-side: Render ChatKit
import { ChatKit, useChatKit } from '@openai/chatkit-react';

export function MyChat() {
  const { control } = useChatKit({
    api: {
      async getClientSecret() {
        const res = await fetch('/api/chatkit/session', { method: 'POST' });
        const { client_secret } = await res.json();
        return client_secret;
      },
    },
  });

  return <ChatKit control={control} className="h-[600px] w-[320px]" />;
}
```

Your users will interact with a chat interface powered by your Agent Builder workflow, with full access to the tools from your Gram MCP server. You can then embed this chat interface into your own website or application.

### Option 2: Advanced integration (Download SDK code)

For maximum control, click **Code** → **Advanced integration** to download the generated Python or TypeScript code. This lets you run the workflow on your own infrastructure with full control over hosting, scaling, custom UI implementation, and advanced error handling.

## Advanced workflow patterns

Agent Builder supports complex multi-agent workflows. Here are some advanced patterns:

### Multi-agent workflows with conditional routing

You can build sophisticated workflows that use multiple specialized agents with conditional logic to route requests:

1. Create a **Classification Agent** that determines the type of request
2. Add an **If/else** logic node to route based on the classification
3. Create specialized agents for different domains:
   - **Task Manager Agent**: Handles to-do operations
   - **Calendar Agent**: Manages scheduling (requires a calendar MCP server)
   - **Information Agent**: Answers questions from a knowledge base

**Using If/else nodes for conditional logic:**

- Add an **If/else** node after your classification agent
- Write conditions using [Common Expression Language (CEL)](https://cel.dev/)
- Route to different agent paths based on:
  - Tool call results
  - User input patterns
  - Agent classifications
  - Data from MCP servers

Here's an example of a multi-agent workflow with conditional routing:

![Screenshot of multi-agent workflow with If/else routing](/img/guides/agent-builder/multi-agent-handoff.png)

In this workflow, user requests are classified and routed to the appropriate specialized agent based on the request type.

### Integration with multiple MCP servers

Connect multiple Gram MCP servers to create powerful cross-system agents:

1. Add multiple **MCP** nodes to your workflow, each configured for a different Gram server
2. Create agents that can access tools from different systems
3. Use logic nodes to orchestrate operations across systems

For example: "Create a task in Taskmaster, then add a calendar event, then send a notification via Slack"—each action handled by a different MCP server.

### Human approval workflows

For sensitive operations, add human approval to ensure oversight before executing critical actions:

1. Add a **Human approval** node before critical operations (like deleting tasks or sending emails)
2. Configure the approval prompt and timeout behavior
3. Route the workflow differently based on approval/rejection

![Screenshot of human approval workflow](/img/guides/agent-builder/human-approval.png)

This is useful for workflows where agents draft emails, make purchases, delete data, or perform other operations that need human oversight before execution.

## Troubleshooting

### MCP node not connecting

**Symptom:** MCP node shows connection errors or fails to list tools.

**Solution:**
1. Test your Gram MCP server in the Gram Playground to verify it's working correctly
2. Verify the Server URL is correct (copy directly from Gram's MCP tab)
3. Check that your server visibility is set to **Public** in Gram (or provide correct authentication)
4. Ensure the server URL includes the correct protocol (`https://`)
5. For authenticated servers, verify your Gram API key is valid and properly formatted

### Tools not working as expected

**Symptom:** Agent calls tools but returns errors or unexpected results.

**Solution:**
1. Check tool definitions in your Gram toolset—ensure descriptions are clear and accurate
2. Verify environment variables are set correctly in Gram
3. Test the tools directly in Gram Playground
4. Review the trace view in Agent Builder Preview to see exact tool call parameters and responses
5. Update your agent instructions to be more specific about when and how to use tools

### Authentication errors

**Symptom:** "Unauthorized" or "403 Forbidden" errors when the workflow calls MCP tools.

**Solution:**
1. For **public servers:** Verify your MCP server visibility is set to **Public** in Gram
2. For **authenticated servers:**
   - Confirm your Gram API key is valid (check in Gram **Settings → API Keys**)
   - Ensure you're providing the Bearer token in the correct format in the MCP node
   - Verify the API key hasn't expired or been revoked

### Agent not using tools

**Symptom:** Agent responds but never calls your MCP tools.

**Solution:**
1. Make agent instructions more explicit about when to use tools
2. Verify the MCP node is properly connected in the workflow
3. Check that tools are being listed successfully (look for `mcp_list_tools` in Preview traces)
4. Ensure tool descriptions in Gram are clear and indicate when the tool should be used
5. Try more direct prompts that clearly require tool usage (for example, "Create a task called X" instead of "I need to remember to do X")
